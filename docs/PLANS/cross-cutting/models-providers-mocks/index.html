Models › Providers: four ways to put providers, keys and models together

The Providers tab today is one folding section per provider, each holding a key list, an always-open "Add a key" form, "Remove all" buttons and a hidden Add a model. Below: four layouts and one shared "connect a provider" flow. Data is yours: OpenRouter key dev (••53f5) with 1 model, NVIDIA NIM key nvidia-dev (••5nk9) with 2, Gemini not set up, 8 local models. Only masked keys appear. ?theme=light for paper. Nothing is built; pick one (or mix) and I will build it. Plan: models-providers-options.md.

  • Provider → key → models, one flow for a first connection and for an extra key. Step 3 lists what the key can call (Jan fetches {base_url}/models on save; Cherry Studio's Manage lists models and you press + on the ones you want; Open WebUI auto-detects and falls back to typing a model id).
  • Hermes Agent does the same in the CLI: hermes model picks a provider, asks for a key, then a model. It has no GUI to copy, so we borrow its order, not a layout.
  • Test connection happens on step 2, so a bad key never reaches the key list.
