# Network: a TLS look (testssl.sh) and a host look (osquery), without showing a fact twice

Branch `network-host-and-tls-looks` (from origin/main `7e952be8`, v0.68.0; it also carries the uncommitted listening-flag and panel-MAC work recorded in `network-host-traffic-and-findings-ui.md`). Owner's request, 2026-11-09: add both tools; when run by hand they may show rich data, in one sensible place and not repeated; during the agent audit the same data should feed the agent. Decision record: ADR-0041 (proposed).

## Order (changed from the first proposal, and why)

`testssl.sh` first. It runs unprivileged, needs the network like nmap (so the existing scope check applies), and most of its output is a fixed vocabulary. osquery second, after a measurement: on Linux a socket's owning process is readable only for the service's own account, on macOS many tables need root or Full Disk Access, and on macOS a guarded program does not start unless the operator allows running unconfined (`progexec.ErrUnconfined`). Building osquery before knowing that would build on a guess.

## The two lanes and the one-home rule

| Fact | Its one home | Manual look (step-up button) | Audit look (module, off by default) |
|---|---|---|---|
| A device's TLS protocols and weak cipher categories | the existing deep check's findings (`tls_weak_protocol`, `tls_weak_cipher`) | the deep check of one device uses testssl.sh when installed | not in the nightly audit (ADR-0012) |
| Certificate expiry and trust | already `webprobe/tls.go` and its findings | not repeated | not repeated |
| This computer's open ports on macOS | the existing `new_listener` finding | n/a | same finding, macOS reader added behind `HostSource` |
| The program behind a connection (text) | the Traffic place panel, this computer's own conversations only | shown as text | never leaves the view; the agent gets counts |
| Raw osquery tables | one "This computer" detail view, behind a button | shown as text | never |

Rule: a finding holds severity; a detail view holds only what a finding cannot, and links to it. The agent reads findings and typed counts, never the raw text of a manual look.

## testssl.sh (revised 2026-11-09: part of the deep check, not a new module)

**What changed and why.** The first version of this plan added a nightly "encryption checks" module and a new device-row section. Reading `deep.go` and `scandeep.go` (after code was started, then backed out) showed the **deep check of one device already makes `tls_weak_protocol` and `tls_weak_cipher`** with nmap's `ssl-enum-ciphers`, has its own dialog and result view, and is kept out of the nightly audit by ADR-0012 because it makes dozens of handshakes; `testssl.sh -p -s` makes hundreds. A nightly module would have shown the same facts twice and broken that rule. So `testssl.sh` is a **closer look inside the existing deep check**, with no new screen.

- **How it works** (`core/netaudit/encryptionfindings.go`, `scandeep.go`, wired in `app/netaudit.go`): after nmap's deep pass, if `testssl.sh` is installed, the device's TLS ports (at most 3; by service name or well-known port) are looked at by the guarded program. The address is checked against the scan scope in the core first (`testssl.Engine`, ADR-0039). For each port, each check the program **judged** (it gave a verdict for at least one protocol or cipher category and none was unknown) **replaces nmap's finding for that port**; what it could not judge stays as nmap said. The check ids are the existing ones, so the key is the same and one fact is one finding. A failed look adds one fixed warning naming the port; a program that is not installed adds nothing.
- **Program** `testssl.sh` through `isolation.Runner`; arguments fixed in `testssl/argv.go` (`-p`, `-s`, quiet, JSON file; never `-U`, `-S` or per-connection timeouts, which need a `timeout` binary that macOS lacks in the jail's PATH). Typed result only: protocols and weak cipher categories as enums (`testssl/types.go`, `parse.go`); every other line is dropped. The CBC suites testssl.sh calls obsoleted are **not** judged: a stock server offers them.
- **Built, uncommitted:** `testssl/` package (T1, T2), the deep-check merge (`TLSLookFindings`, `refineTLS`, `WithTLSLooker`), the app wiring. Tests: `go test ./internal/core/netaudit/...`; complexity clean.
- **Not installed says so (added 2026-11-09 at the owner's request):** `isolation.Present` / `progexec.Lookup` check the PATH without starting a process; `Readiness.Notices()` adds `testssl_missing` with the install command for the OS (`brew install testssl`, `sudo apt install testssl.sh`) as a copy fix; the readiness banner (settings and automation pages) shows it as a note; the deep-check dialog tells the truth about what it will send in each state (installed: a few hundred connections, at most 3 services; missing or unknown: about 60, with the command). Files: `testssl/engine.go` (`Present`), `core/netaudit/readiness.go`, `FindingsReport.vue`, `DeepCheckDialog.vue`, `constants/netaudit.ts`; SPEC-003 2.57.
- **Not built, and not needed:** a nightly module, a config switch, a device-row section, a new route.
- **Not verified:** a real device (not loopback); Linux (the Landlock jail's reads); whether the deep-check route shows `Result.Warnings` to the person (not read: a failed closer look adds a warning the screen may not show); the total time of a deep check with three looks (`DeepBudget` 6 min for nmap plus `DeepTLSBudget` 6 min) against the HTTP server's write timeout (not read); the macOS unconfined opt-in. The deep check on a Mac asks nmap first, so the closer look runs only where nmap does.

## osquery and the host look (revised 2026-11-09 after measuring and after reading the helper)

- **O0 measured.** **Mac:** osquery 5.24.1, unpacked from the Homebrew cask's `.pkg` into a scratch folder and run in shell mode as the ordinary user, no sudo: `listening_ports` gave a pid and a program name for all 10 rows with port not 0, `process_open_sockets` a pid for 18 of 18, `launchd` listed the plists, a query took about 0.25 s, and nothing was left behind but the database folder named. UDP rows come with port 0 (filter `port != 0`). `brew install --cask osquery` can say "already installed" when the `.pkg` was downloaded and the installer never ran (it needs `sudo installer`). **Linux (vertex), as the owner's ordinary account:** all 44 listening-port rows had `pid` -1 and no name; the service's account has fewer rights, so it cannot do better. So **osquery cannot name the program behind a connection on Linux without root.**
- **Program names on Linux through the privileged helper: reversed, not built.** I recommended a pure-Go helper action. Reading the helper (`cmd/llm-proxy-helper/main.go`, `privhelper/catalog`) showed the net class holds only `CAP_NET_RAW`, and reading which process holds another account's socket (`/proc/<pid>/fd`) needs **`CAP_SYS_PTRACE`**, which lets the holder inspect and alter any process: a new privilege class, unit and socket for a screen nicety, against the grain of I.11. Not worth it. What an unprivileged service can read is the **owning account** of each socket (the uid column of `/proc/net/tcp`, mapped through `/etc/passwd`), but only for connections open at the time of the lookup; a listen that ended a minute ago has mostly closed them. Left as an idea, not built.
- **macOS host look: built without osquery** (O1 became this). Measured on this Mac: the host watch used to fail outright (`Look` returned "failed to list the open ports") so nothing ran. Now `Look` treats a computer that cannot list its ports (`ErrUnavailable`) as **ports not checked**: the startup files are still compared, no ports baseline is kept, no port finding is made and the report says so (`HostLook.PortsUnchecked`). The existing test that pinned the old behaviour (`ACannotCheckIsAnErrorAndNeverABaseline`) was replaced on purpose; any other failure to list ports is still an error. macOS gains the places a program starts at boot and at login (`launch_daemons`, `launch_agents`, with fix guides) and the SSH keys under `/Users`. A first look on this Mac gave 0 findings, ports unchecked, 1 place unreadable (not run as root). A **false finding was caught and fixed on the way**: the SSH password-login check fired on macOS because `sshd_config` exists whether or not Remote Login is on; `hardenerFor` now leaves the SSH server's settings out off Linux.
- **Open ports on macOS: built in pure Go, 2026-11-10 (owner chose it over a `netstat`/osquery program).** `platform/hostwatch/pcblist.go` reads the kernel's own tables (`sysctl net.inet.tcp.pcblist_n`, `net.inet.udp.pcblist_n`, through `golang.org/x/sys/unix`, in process: no program, so no unconfined opt-in; `sockets_darwin.go`, `Source.Listeners` falls back to it when there is no `/proc`). Same rules as Linux: TCP in the listening state, UDP bound and unconnected, never loopback, never a socket this program holds (matched by `so_last_pid`, where Linux matches inodes), no UDP port in the dynamic range (`net.inet.ip.portrange.first`, 49152). Only a protocol and a port are kept. **Layout, read from the real kernel and checked against `lsof` on this Mac** (all seven `lsof` listeners were found, plus three only root can see): records are packed to 4 bytes and padded to 8 in the buffer; per socket the order is the port record (`0x010`), the socket record (`0x001`), buffers and counters (`0x002`, `0x004`, `0x008`) and, for TCP, `0x020`; in the port record `inp_fport` is at 16, `inp_lport` at 18 (network order), the family byte at 44 (1 IPv4, 2 IPv6; 3 for both) and the local address at 64 (an IPv4 address is in the last four of the sixteen bytes); the socket record's `so_last_pid` is at 68; the TCP record's `t_state` is at 36 (1 is listening). A buffer that does not fit (no header or trailer, a record too short or past the end, a record out of order) is `ErrUnavailable`, so the report says the ports were not checked and never "nothing is listening". Tests: real kernel bytes in `testdata/macos_{tcp,udp}_pcblist.hex` (only the test process's own sockets), the layout error cases, a real record patched to loopback in both families, and a darwin-only test against the live kernel. Four offset mutants were each shown to fail the tests. **Not verified:** other macOS versions (the layout is the one macOS has had since 10.7 per the kernel headers I know, but only this Mac, macOS 27 on arm64, was read); an Intel Mac (little-endian, the same layout; not run); the program name behind a port is left out on purpose, as on Linux.

## Remaining Work (2026-11-09)

**Built, uncommitted on this branch.** T1 and T2 in `backend/internal/core/netaudit/testssl/`: the fixed argument list (`argv.go`; never `-U`, `-S` or any flag from a request), the typed parser (`parse.go`, `types.go`: protocols and cipher categories as enums; every other line dropped; "offered" and "not offered" are the only readable verdicts, anything else is `unknown`; a file that names none is an error), and the engine (`engine.go`: scope checked in the core before anything starts and held to the one address asked for, a private scratch folder removed afterwards, a run that is cut short or unreadable gives no verdicts). Tests: `go test -race` on the package; the two scope tests were shown to fail with the check removed and pass with it restored.

**Checks run:** `go build ./...`, `go run ./tools/check-complexity/`, `go test -race ./internal/core/netaudit/testssl/`, `./scripts/check-agent-harness.sh`. **Not run:** the whole Go suite after T1/T2 (nothing outside the new package changed), anything with the real program.

**Measured on macOS 2026-11-09** (testssl.sh 3.2.5 from Homebrew, against a throwaway `openssl s_server` on loopback; nothing on the network was touched): (1) a real file is now the fixture (`testdata/macos-loopback-openssl-server.json`) and the ids and words match what the parser reads: a flat array, `TLS1_1`, `cipherlist_3DES_IDEA`, "not offered", "offered with final". (2) The whole path works through the real guarded runner (`TESTSSL_LIVE_UNCONFINED=1 TESTSSL_LIVE_TARGET=127.0.0.1:8443 go test ./internal/core/netaudit/testssl/ -run Live -v`, 8.7 s). (3) **macOS refuses by default**: no file confinement, so `ErrUnconfined` unless the operator allows running unconfined; the module must say that plainly on macOS. (4) **`--connect-timeout` made testssl.sh fail** ("couldn't find the binary timeout") under the clean PATH `/usr/bin:/bin`, because macOS has no `timeout` there; both timeout flags were removed and the runner's 3-minute limit bounds the look. (5) A stock OpenSSL server offers `cipherlist_OBSOLETED` (the CBC suites, severity LOW): T3 must **not** make that a finding; only NULL, anonymous, export, low and 3DES/IDEA are weak.

**Still not verified:** Linux (the Landlock jail's read access to `/usr`, `/etc/ssl` and a bash and openssl); a real device rather than loopback (a device that closes the connection, answers slowly or speaks STARTTLS); whether a look fits `lookTimeout` against a slow device; the system openssl in the jail on macOS (`/usr/bin/openssl` is LibreSSL 3.3.6, so SSLv2/SSLv3 may come back as "not tested", which the parser reads as unknown and not as clean).

**Linux, measured in a container 2026-11-10** (Ubuntu-kernel Docker VM, Debian `testssl.sh` 3.x, OpenSSL 3.5 `s_server` on loopback; nothing on a network was touched):
1. **Debian and Ubuntu install the program as `testssl`, not `testssl.sh`.** The look said "not installed" even after `sudo apt install testssl.sh`. Fixed: `progexec.Program.Alternates` (tried after `Binary`), `testssl.Program` lists `testssl`; test `TestLookup_FindsAProgramUnderAnotherNameItIsPackagedAs`.
2. **The jailed look on Linux does not work yet.** Run directly with the same arguments and a clean environment, the program finishes in 5 to 9 seconds with verdicts. Run through the real runner (Landlock on in the container), it prints its first two lines (start, reverse DNS) and then stalls: the live test took 147 s and the file held no protocol as offered. Granting the folder the `/usr/bin/testssl` link points to (`/usr/share/testssl.sh`, `readPathsFor`) did not change it. **Cause not found**; `TESTSSL_LIVE_UNCONFINED=1` does not remove the wrapper when the kernel supports Landlock, so that run was not an unjailed one. Next step: run the program under `strace -f` inside the jail, or find which path or syscall it needs (seccomp profile, `/dev/tcp` through bash, a temp file outside the scratch folder).
3. **A false all-clear was possible and is closed.** The 147 s run first read as "TLS 1.2 not offered, everything else not offered", which the merge would have treated as a clean answer and used to replace nmap's findings. `Parse` now refuses a file in which no protocol is offered (`ErrUnreadable`; `TestParse_AFileThatOffersNoProtocolAtAllIsAnErrorNotAnAllClear`), so a look that never reached the service becomes the fixed warning and nmap's answer stays. On Linux today that is what happens: the deep check shows nmap's result plus "The closer look at the encryption on port N did not work".
4. **The warning reaches the screen now.** `models.DeepCheck.Warnings` is kept and returned (`deepCheckView.warnings`), and `DeepCheckResult.vue` shows each one (`data-test="deep-warning"`). Before this, `Result.Warnings` was dropped when the check was stored, so the screen never showed that a closer look failed. The HTTP write timeout is 30 minutes (`app/app.go:181`), above the worst case of two 6-minute budgets.

**Still not verified:** the jail on Linux (item 2); a real device rather than loopback; a look against a slow device within `lookTimeout` (3 minutes) and the dialog's wording "a minute or two for each"; the system openssl in the jail on macOS (LibreSSL, SSLv2/SSLv3 may come back "not tested", which reads as unknown); macOS with the unconfined opt-in on.

**Next, in order:** (1) find why the jailed look stalls on Linux (item 2); until then the closer look works on macOS with the unconfined opt-in and on Linux only unjailed. (2) osquery stays unbuilt: it cannot name a program on Linux without root (measured on vertex), and the macOS look is built without it. (3) Version number and commit: the owner's.
