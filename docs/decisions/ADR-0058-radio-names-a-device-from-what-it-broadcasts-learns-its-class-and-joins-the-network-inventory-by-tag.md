# ADR-0058: Radio names a device from what it broadcasts, learns its class from the owner's answers, and joins the network inventory by tag

Proposed 2026-11-17. The owner decided every point below in conversation on 2026-11-17 ("show make and model for router and devices that we can identify; keep the one box grouping if it is useful and everything else you asked for decisions; we need an auto classification technique to learn and adjust a category"). It becomes accepted when the owner merges the pull request that carries it and the amended Constitution I.16. Amends [ADR-0053](ADR-0053-radio-keeps-a-keyed-tag-for-other-peoples-devices-and-seals-the-owners-with-hard-size-and-age-limits.md) and [ADR-0057](ADR-0057-radio-keeps-the-maker-and-wi-fi-generation-of-a-device-next-to-its-tag-and-a-network-name-in-memory-only.md) on what is kept beside a tag.

## Context
The owner called the Radio page useless: a row read "SKY UK 2a6e3b0d" and nothing said whether it was theirs. Measured on vertex (read-only, 2026-11-17): 0 of 56 devices were marked as on the owner's network after 353 cycles with 4 confirmed access points, because only an association request (sent once, at connection) set the mark; the parser read every data frame's BSSID and the recorder dropped it. The classifier was hand-written thresholds; "This is mine" taught it nothing. Research: `docs/audits/2026-11-17-radio-identification-research.md` (WIPS wired-side correlation, Kismet's client and related-device model, client taxonomy, WPS, per-network private addresses, few-label learning).

## Decision
1. **Who a device talks to.** Each cycle the recorder links a device to the access point it exchanged data frames, RTS or block acknowledgements with (or asked to join) and stores the AP's keyed tag (`devices.net`). A link to one of the owner's confirmed, non-guest access points marks `joined_own` and counts `own_cycles`. A guest network is a per-AP flag the owner sets; a device on it is not evidence. Evidence is never ownership: only the owner's word makes a device theirs.
2. **One box.** The radios of one router (2.4 GHz, 5 GHz, guest, backhaul) share a keyed box tag derived in the recorder from the address block with the locally administered bits and the last three bits cleared (`boxKey`), stable whichever radio is heard first. Different makers never share one.
3. **What it says it is.** From the WPS element (beacons, probe responses and requests, association requests): manufacturer, model name (with the model number when it is not a firmware version) and the primary device type; **never the WPS Device Name**. From a vendor element: the company (a hint, worded as one). From a probe or association request: a 64-bit sum of its element layout, said to mean "the same kind of device", never "the same device". Text is cleaned to printable ASCII and capped at 40 characters.
4. **Kind.** What a device is (router, phone, TV, ...) comes from an evidence ladder: the owner's word, the WPS type, the model name, what the owner said about other devices of the same maker (label spreading), sending beacons, the maker's usual products, a vendor hint, a private address. The answer carries its source and confidence. Only the owner's kind is stored; the rest is worked out when the page asks.
5. **Class, learned.** Rules version 3: a naive Bayes model whose prior is the version 2 thresholds (four made-up examples per class), retrained every cycle from the window: the owner's answers weigh 6, hard evidence (on the owner's Wi-Fi, a never-strong access point) 2, the rules' own answers 0.3 with a cap of 40 per class. Training afresh each cycle means it cannot drift. A device moves class only when the new class leads by 0.15 for two classifications in a row; a device not yet sorted stays Unknown below 0.55, and one already sorted keeps its class when the model is unsure. The owner's "This is mine" records ownership only and teaches no class; "Not mine" is stored as a neighbour's or a passer-by, whichever the current model rates higher, so the answer does not teach that passers-by are neighbours. The device page explains a class with the stored model the last cycle decided with, over the same evidence (the inventory join applied). Each change is logged with its reason. The model document holds per-class sums only, and how many owner answers it gives back when each is held out.
6. **The network inventory, by tag.** A new SDK port, `lan`: the core tags every inventory address, and the gateway's address with its neighbours (plus and minus 8, plain and with the locally administered bit flipped, as Aruba's "minus one" and AirDefense's BSSID range do), under the purpose the stack asks for, and returns the tags with the operator's names. No address crosses; nothing is stored; the names are shown on the Radio page only.
7. **Evidence borrowed from nodeherder's wireless observations** (branch `feat/wireless-observations`, spec 065, read 2026-11-17): a day's evidence weighs half as much every 2 days (recency weighting, counted from the latest listened day so the answer is reproducible); one bit a day for "heard between 01:00 and 05:00 local time" (always-on equipment; never the hour); a count of cycles whose mean signal jumped 10 dB or more from the cycle before, read as the share of heard cycles (movement, independent of how many cycles run); signals shifted so the owner's own access points read as -45 dBm at their strongest (capped at 15 dB; nodeherder's "below the strongest device in the room"); a first-look guess (a private address that is no access point: someone's phone; never strong: a neighbour's) shown as a guess before the sorting has evidence; and an evidence line on the device page in numbers the owner can check.
8. **The page.** A device is named by: the owner's label, its name on the network, its make and model, its maker and kind, the network it broadcasts, its maker, its kind; never by its short id. Rows lead with whose it probably is. New: a device page (`/radio/device/:id`), a networks view (routers with their clients), a "help it learn" card, zoom on the radar (buttons, wheel, pinch), a solo radar that draws the distance band all the way round.

## Consequences
- Migration 8 adds the columns; "forget neighbours" clears every `net` and `box` reference; a test reads the file and finds neither an address, a WPS device name nor a network name.
- The live answer grows by one `ident` object per dot. Kept lean: the evidence and the relatives are on the device page's own endpoint.
- A neighbour's maker, model and kind narrow who they are more than a tag alone. The legal position of ADR-0053 is unchanged and stays with the owner.
- Bluetooth and a second sensor in another room are not built here (a new helper action is a security review of its own, I.17; a second place needs hardware). nodeherder takes BLE advertisements from ESPHome Bluetooth proxies on the LAN; the same shape (a remote sensor as a `Sensor` with capabilities, reached through the scoped guard) is the proposed route for both, and needs an ADR and a Constitution item of its own.

## Alternatives considered
- **Store the client to access point link only for the owner's devices**: leaves the neighbours' networks unreadable, which was the complaint.
- **A trained black-box model (gradient boosting, a neural net)**: no labelled data to train it, and the owner asked to see why. Naive Bayes over a few numbers explains each decision by its largest terms.
- **nodeherder's rule scores without learning** (ADR-002 there, "rule-based, not a learned model"): explainable, but the owner asked for categories that adjust as data arrives; the naive Bayes keeps the explanation (per-feature terms) and learns.
- **Its write floor** (a day kept only after 2 hours and 20 packets): would lose the passers-by the transient class is made of; the 20 MB cap and 14-day age already bound the file.
- **Self-training without a cap**: confirms its own mistakes; capped and retrained from scratch each cycle instead.
- **The core sends the stack the inventory's addresses**: the stack would hold addresses of the owner's devices it never sealed; tags under the stack's own purpose give the same join with nothing to leak.
