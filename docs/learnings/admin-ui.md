# Learnings — Admin UI and chat rendering (SPEC-003)

What was tried and what happened. Read before proposing an approach in this area; add a line when a run,
eval, audit or merged phase teaches something (newest last within each section). Format and rules:
[`README.md`](README.md).

## Dead ends — do not retry without new evidence

- **Tried:** Animating hidden elements, `backdrop-blur` on always-visible surfaces, box-shadow keyframes → **constant GPU cost on macOS**. **Lesson:** gate the animation itself; solid backgrounds; opacity/transform-only indicators. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** Measuring GPU with a telemetry loop that uses `requestAnimationFrame` → **the meter itself created phantom GPU load**. **Lesson:** measurement tooling must not animate. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).

## Root causes and fixes that held

- **Tried:** Deep `watch` on unbounded arrays; `.some()` dedup over all live events → **O(n²) per event**. **Lesson:** watch by reference/length; one shared `Set`-based event-id deduper. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** Full text-node replacement and nested auto-scrollers while streaming → **whole-region re-raster per flush**. **Lesson:** incremental append; one scroller. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** Measuring a frontend change without rebuilding the Go binary → **old UI measured (`go:embed`)**. **Lesson:** rebuild Go, restart, hard-refresh before measuring. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** `messageBuilder.reset()` and multi-message turn grouping → **stale reasoning in the next turn; grouper used the first message's segments**. **Lesson:** reset `liveReasoning`; use the last message's segments. Evidence: [2026-06-26-stale-turn-bleed.md](../audits/2026-06-26-stale-turn-bleed.md).
- 2026-10-29: a command that writes a file the running service must read has to act on the service's own folder as the service's account. `llm-proxy auth setup-code` typed from a checkout wrote to the typist's `~/.config/llm-proxy` and the deployed service (own user, `LLM_PROXY_HOME=/var/lib/llm-proxy`) never saw the code; `setup_open` stayed false and `/admin/setup` redirected home. The command now chooses the folder as the server does, becomes the account that owns the folder (not the unit's `User=`), and checks a marker (`server.json`) the running server keeps in its folder; guessing from the unit alone has blind spots (drop-ins), a check does not. A plain `sudo` with an explicit `--data` would be worse: a root-owned 0600 file the service cannot read, so every admin request answers 503.
- 2026-10-29: the sign-in state is read once at start, so a route guard that trusts it goes stale while the page is open (a setup code made on the server later, a passphrase set in another tab). `startAuth` asks the server again for the public sign-in pages; the first deploy redirected `/setup` home because it still believed "no setup code".
- 2026-10-30: the design said a composer draft survives 401 -> login -> back; it did not. `/login` is a `bare` route (`App.vue`), which removes the whole shell including `KeepAlive`, so `AssistantChat`'s local `inputMessage` was destroyed. Fix: `useComposerDraft` keeps the text in memory per workspace on unmount and restores it on mount (never in storage: a draft can hold anything). A claim about UI state surviving navigation needs a test that unmounts the component. Evidence: [useComposerDraft.ts](../../frontend/src/composables/assistant/useComposerDraft.ts), [AssistantChat.component.test.ts](../../frontend/src/__TESTS__/components/AgentIde/assistant/AssistantChat.component.test.ts).
- 2026-11-01: **a GGUF file moved into a subfolder of the model folder could not be added: "model file not found", however often it was rescanned.** Two causes. (1) "Discovered on disk" offered the file with its full path (`resolved_path`) but the add sent only the bare file name, and the server joins that to the model folder (`ResolveModelPath`), so only files directly in it could ever be found; the add now also sends `path` while the file name is still the picked one (a name typed by hand is looked up in the model folder as before). (2) The scan cache (`modelDiscoveryCache`) was invalidated by the change time of the model folder alone, which does not move when a file is added, removed or moved inside an existing subfolder, so a rescan could keep showing the old list; it now keeps the unfiltered scan, watches every folder's change time, and applies the "already added" filter on each request (an added model stops being offered, a removed one comes back, without anything changing on disk). **Known limit:** the Added tag in the UI matches on file name, so two files with the same name in different folders share it. Tests: `admin_handlers_test.go` (`AvailableSeesAFileAddedInsideAnExistingSubfolder`, `AvailableFollowsWhichModelsAreRegistered`), `ProviderModelsCard.component.test.ts`.
- 2026-11-05 (stacks P1, v0.48.0): the navigation group is **Stacks** (Network, Agents) and every switch of a stack is on its Modules tab only, so a detail card shows `ModuleSwitchNote` (on or off in words, a link to the tab, the old hint and "More about this") where its switch was; the old per-card setters (`set` in `useDecoys`, `useRouterLog`, `useNearby`, `useOutsideLookup`, `useDnsCheck`, `setIPv6`) and their service methods were removed, not left unused. Settings → Safety → Agent activity moved to Agents → Activity, so `'agent-activity'` left `SettingsTab`, `useProviders().settingsTabs` and the settings groups (the ledger's trap: a Settings section must be in all three). See the network-audit ledger for the traps met.
- **Test trap (2026-11-09):** `beforeEach(() => service.thing.mockReset())` returns the mock, and Vitest runs a function returned from a hook as its cleanup, so the mock is called after the test (here with a rejected value, which failed the test with the mock's own error). Write the hook with braces and no return.
