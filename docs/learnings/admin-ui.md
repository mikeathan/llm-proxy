# Learnings — Admin UI and chat rendering (SPEC-003)

What was tried and what happened. Read before proposing an approach in this area; add a line when a run,
eval, audit or merged phase teaches something (newest last within each section). Format and rules:
[`README.md`](README.md).

## Dead ends — do not retry without new evidence

- **Tried:** Animating hidden elements, `backdrop-blur` on always-visible surfaces, box-shadow keyframes → **constant GPU cost on macOS**. **Lesson:** gate the animation itself; solid backgrounds; opacity/transform-only indicators. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** Measuring GPU with a telemetry loop that uses `requestAnimationFrame` → **the meter itself created phantom GPU load**. **Lesson:** measurement tooling must not animate. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).

## Root causes and fixes that held

- **Tried:** Deep `watch` on unbounded arrays; `.some()` dedup over all live events → **O(n²) per event**. **Lesson:** watch by reference/length; one shared `Set`-based event-id deduper. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** Full text-node replacement and nested auto-scrollers while streaming → **whole-region re-raster per flush**. **Lesson:** incremental append; one scroller. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** Measuring a frontend change without rebuilding the Go binary → **old UI measured (`go:embed`)**. **Lesson:** rebuild Go, restart, hard-refresh before measuring. Evidence: [gpu-performance-audit.md](../audits/gpu-performance-audit.md).
- **Tried:** `messageBuilder.reset()` and multi-message turn grouping → **stale reasoning in the next turn; grouper used the first message's segments**. **Lesson:** reset `liveReasoning`; use the last message's segments. Evidence: [2026-06-26-stale-turn-bleed.md](../audits/2026-06-26-stale-turn-bleed.md).
- 2026-10-29: a command that writes a file the running service must read has to act on the service's own folder as the service's account. `llm-proxy auth setup-code` typed from a checkout wrote to the typist's `~/.config/llm-proxy` and the deployed service (own user, `LLM_PROXY_HOME=/var/lib/llm-proxy`) never saw the code; `setup_open` stayed false and `/admin/setup` redirected home. The command now chooses the folder as the server does, becomes the account that owns the folder (not the unit's `User=`), and checks a marker (`server.json`) the running server keeps in its folder; guessing from the unit alone has blind spots (drop-ins), a check does not. A plain `sudo` with an explicit `--data` would be worse: a root-owned 0600 file the service cannot read, so every admin request answers 503.
- 2026-10-29: the sign-in state is read once at start, so a route guard that trusts it goes stale while the page is open (a setup code made on the server later, a passphrase set in another tab). `startAuth` asks the server again for the public sign-in pages; the first deploy redirected `/setup` home because it still believed "no setup code".
- 2026-10-30: the design said a composer draft survives 401 -> login -> back; it did not. `/login` is a `bare` route (`App.vue`), which removes the whole shell including `KeepAlive`, so `AssistantChat`'s local `inputMessage` was destroyed. Fix: `useComposerDraft` keeps the text in memory per workspace on unmount and restores it on mount (never in storage: a draft can hold anything). A claim about UI state surviving navigation needs a test that unmounts the component. Evidence: [useComposerDraft.ts](../../frontend/src/composables/assistant/useComposerDraft.ts), [AssistantChat.component.test.ts](../../frontend/src/__TESTS__/components/AgentIde/assistant/AssistantChat.component.test.ts).
- 2026-11-01: **a GGUF file moved into a subfolder of the model folder could not be added: "model file not found", however often it was rescanned.** Two causes. (1) "Discovered on disk" offered the file with its full path (`resolved_path`) but the add sent only the bare file name, and the server joins that to the model folder (`ResolveModelPath`), so only files directly in it could ever be found; the add now also sends `path` while the file name is still the picked one (a name typed by hand is looked up in the model folder as before). (2) The scan cache (`modelDiscoveryCache`) was invalidated by the change time of the model folder alone, which does not move when a file is added, removed or moved inside an existing subfolder, so a rescan could keep showing the old list; it now keeps the unfiltered scan, watches every folder's change time, and applies the "already added" filter on each request (an added model stops being offered, a removed one comes back, without anything changing on disk). **Known limit:** the Added tag in the UI matches on file name, so two files with the same name in different folders share it. Tests: `admin_handlers_test.go` (`AvailableSeesAFileAddedInsideAnExistingSubfolder`, `AvailableFollowsWhichModelsAreRegistered`), `ProviderModelsCard.component.test.ts`.
- 2026-11-05 (stacks P1, v0.48.0): the navigation group is **Stacks** (Network, Agents) and every switch of a stack is on its Modules tab only, so a detail card shows `ModuleSwitchNote` (on or off in words, a link to the tab, the old hint and "More about this") where its switch was; the old per-card setters (`set` in `useDecoys`, `useRouterLog`, `useNearby`, `useOutsideLookup`, `useDnsCheck`, `setIPv6`) and their service methods were removed, not left unused. Settings → Safety → Agent activity moved to Agents → Activity, so `'agent-activity'` left `SettingsTab`, `useProviders().settingsTabs` and the settings groups (the ledger's trap: a Settings section must be in all three). See the network-audit ledger for the traps met.
- **Test trap (2026-11-09):** `beforeEach(() => service.thing.mockReset())` returns the mock, and Vitest runs a function returned from a hook as its cleanup, so the mock is called after the test (here with a rejected value, which failed the test with the mock's own error). Write the hook with braces and no return.

- 2026-11-11: **a Playwright tap-area check reads the viewport.** `expectTapArea` (`e2e/support/adminApi.ts`) asks `elementFromPoint`, so a control the page has scrolled out of view fails it with all four points false, though it is fine. After a click that scrolls (a segmented switch higher up), `scrollIntoViewIfNeeded()` the control first (`e2e/network-traffic.visual.spec.ts`). Also: moving a card into a Settings group means every visual spec that opens `network/settings` for that card needs `?group=`; nine did.

- 2026-11-19 (dashboard, v0.105.0): **three traps met building the card grid.** (1) A component's `provide` reaches the children of its **own** template: the card frame provided "you are in a card" (so a `Panel` inside draws only its content) and its own `Panel` unwrapped itself, leaving no title. The provide now lives in `DashboardCardBody`, which wraps only the card's content. (2) Choosing a card's version with CSS container queries renders **every** version (the hidden ones still mount), so the radar drew twice, a test saw two of everything and each hidden copy polled. The frame measures its own width and provides a size (`useCardSize`); the card renders one version. (3) A full-width card on a 390 px phone is about 326 px wide and counted as small, which hid the detail where it matters most; below the tablet width the grid is one column and a card is its own block with all the height it needs, so it is large there (`DashboardCardFrame`). Also: a ref returns a reactive **proxy**, so `layout.value === next` is never true after `layout.value = next` (compare `toRaw`); a shared poller's consumer count must be taken in `setup`, not `onMounted`, because when a board changes the new cards are set up before or after the old ones unmount and the count must not reach zero in between (`useNetworkSnapshot`); the radio page's "Around you" was not a tab to keep but a view to move, and what stayed on the page were the decisions (claiming a device). Tried and not needed: a grid or drag library (hand-written drag and CSS grid are enough).

- 2026-11-19 (dashboard, v0.106.0): **the owner's first run found what 3,200 unit tests could not: the card controls.** Resizing stretched the neighbour and "later" moved nothing, because the grid used a row span and gap filling (pitfall 75); unit tests in happy-dom check classes and DOM order, not geometry, so the fix is proved by Playwright reading `boundingBox()`. Also: (1) moving a view to a card exposed the nested-Panel trap (pitfall 74) only in an Advanced-mode spec. (2) A saved layout predates every card added later, and `reconcile` only drops cards, so a page that links to a moved view needs `?card=` and an "Add it" line, not a hope that the board has it. (3) `vue-tsc -p tsconfig.app.json` is the quick typecheck; lint (`no-restricted-syntax`: types only from `src/types/`) runs only in `npm run build`. (4) `useDevices().load()` reads three things; a card that needs only the inventory still pays for presence and IPv6 (left as is: one read per card mount).

- 2026-11-19 (v0.108.0): **a menu entry that opens another page's board is a stack that looks like the Dashboard.** ADR-0066 decision 5 made the sidebar's Network and Radio open `/dashboard?board=`, so the owner saw the Dashboard title, the board tabs, a "Custom" layout and the "New on this board" banner under a stack name, and called it wrong. A stack's menu entry opens the stack's own control page (`toNetwork()`, `toRadio()`; `utils/navigation.ts`); the board is one link or tab away, and on it the Dashboard entry is current. The saved-board "New on this board" offer still shows on a board saved before a card existed (not changed).

- 2026-11-19 (v0.110.1): **A dashboard card scrolls its list at every size.** Recent runs capped its large table at 5 of the 20 runs it keeps with nothing to reach the rest, the same gap v0.110.0's scroll fix left in one size branch. Rule: no card slices its list by size; cap only by a data limit and let `CARD_LIST_SCROLL[size]` bound the height (`RecentRunsCard.vue`).
- 2026-11-19 (v0.110.0): **A stack can be switched all on as well as all off** (`POST .../on`, ADR-0067 amended) because switching many modules one by one was tedious. The two buttons say "Switch stack on/off" because "all off" did not read as disabling the stack. The passphrase follows each module's `StepUp` flag, so Radio (sends nothing) switches without it and Network asks: by design, not an inconsistency (`stacks.go` radioModules).
- 2026-11-19 (v0.109.0): **"No way to disable a stack" was a missing verb, not a missing setting.** A stack was already on exactly while a module of it was on (`useEnabledStacks`), so a stored flag would have been a second truth; the fix is one route that switches the modules off (ADR-0067). Also: the shipped Home repeated every stack board, so it now ships one card nothing else shows (tests that arranged Home's cards now seed a filled Home). Not built, on purpose: the four device lists stay separate cards (table in ADR-0065), a waiting-approvals card (no endpoint), an LLM queue card (Running now covers it).
- 2026-11-19 (v0.111.0): **The last two view-only tabs moved to cards: Radio Sensors and Agents Activity.** The page components were reused unchanged for Sensors (`RadioSensorsCard` wraps `RadioSensors`); Agents' page was split into `AgentLockdown` (the one action, stays) and the existing `AgentsActivityCard` (gained the fetch-destinations list at large size). Second trap: `useDashboard.open()` ignores a board the saved layout lacks, so a stack page's "Open the board" link to a board that shipped after the layout was saved did nothing; `DashboardView.openFromAddress` now adds the shipped board then (a board that did not ship is never made up). Trap: a router-redirect test cannot live in `__TESTS__/router` (the `unit` project has no Vue plugin and cannot load a view the routes import); put it in a view component test, as `Radio.component.test.ts` does.
- 2026-11-19 (v0.113.0, ADR-0070): **The Network board was thirteen cards in one column (2787 px at 2000 px wide with nearly empty mocks).** Measured, not guessed: nine of them were full width, and five of the thirteen read the same `/netaudit/overview`, so they were one answer drawn five times. Tried and rejected: a root tab per Network board (the owner: the top level must not grow), hiding cards in Simple (hidden knowledge). Built: one Network tab with five sub-tabs (a template `group`, no stored-layout change), eight cards merged into three views and one new overview card; every sub-tab is now one screen at 2000×1300 with the mocked data. Traps: the stored board has no group or source, so grouping is read from the shipped template by id (an owner's own board is never grouped); a saved layout drops retired card ids silently and keeps the rest, so the owner presses Reset board once; `?board=` must be a sub-board id for a card to open (`NETWORK_CARD_BOARD`); `MAX_BOARDS` had to rise (12 to 20) because five sub-boards left two for the owner. Also: the constant scrollbar flicker on a big screen was a scrollbar-width feedback loop (pitfall 76), fixed with `scrollbar-gutter: stable`.
- 2026-11-25: Compact page heads (v0.140.0). Three traps the browser specs caught and happy-dom could not: (1) removing a `relative` container (the dashboard tab row lost it with Add board) let the tab dot's absolutely placed `sr-only` words escape the scrolling strip and widen the page by 2 px; keep `relative` on any row that holds `sr-only` text (`DashboardBoardTabs.vue`). (2) A pseudo-element hit area's inset counts from inside the border: a 26 px outline button needs `before:-inset-y-[10px]`, not 9, for a 44 px target (`NewsroomView.vue` Follow). (3) Measure tap areas and offsets after the route transition (`.route-enter-active` gone): the page slides in, and a box read mid-slide misses by a pixel.

- 2026-11-25 (v0.141.0, ADR-0089): **The Newsroom moved onto the dashboard as page boards, not as a card.** A board template with a `view` draws one component in place of the grid, so the brief kept its layout exactly (compared before and after with `SCREENSHOTS=1` renders) and needed no stored-layout or server change. Tried and dropped: a "Following and settings →" link at the end of the sub-tab row (in the mock); each view already links to its setup and the extra row cost a phone ~45 px. Found on the way: the phone summary linked to `/newsroom`, but the admin UI is served only under `/admin/` (`handlers/admin_ui.go`), so the link could never open; it now carries the prefix. Trap: `DashboardBoardTabs` now reads `useAlertsUnread` too, so every test that mounts it or `DashboardView` mocks `NewsroomService.alertCounts` and resets the poller in `beforeEach`.

- 2026-11-26 (v0.142.0): **Editing a local model failed on Save with "Please select a valid value" (reasoning budget 29127).** Cause: browser constraint validation, not the server: the field had `step="128"` and the server derives the budget as max tokens / 3, so 29127 sits off the grid; max tokens (`step="64"`) and the context budget (`max="100000"`) had the same trap on cloud models. The three derived fields now carry only `min` (pitfall 78). **Found on the way:** the server clears a local model's submitted reasoning budget (tested in `model_handlers_test.go`), so a number typed there was silently dropped on save; the field is now read-only on local models. An untouched Save does not pin the derived 29127 (the override is written as 0 and `/state` fills the view). **The 16 `/design` visual cases were never flaky:** every run since #313 failed the same way (desktop 52 px taller, phone 12 px shorter) because #313 added the `text-title` type sample and the phone page head drops its eyebrow and subtitle, and nobody refreshed the baselines; the diff starts exactly at the new row. Refreshed after reading the diff. **The connection-refused noise** (2,824 `ECONNREFUSED` lines, 5.9 MB of output per full run) came from pollers and services that tests did not mock, printed with no test name, so per-file stubbing (the 2026-10-28 network-audit fix) kept drifting back; a component-project setup file (`__TESTS__/setup/noNetwork.ts`) now makes an un-mocked fetch reject at once: 0 lines, 27 KB of output, 3,646 tests still pass.
- 2026-11-26 (v0.142.0, ADR-0090, Constitution III.8 amended): **Models became one page** (cards or a list with a side-panel editor, Providers, Engine, Routing; reading on Dashboard › LLM and host; a Running model section in System stats). Mocks first (`ARCHIVE/cross-cutting/models-redesign-mocks/`): the owner picked option A (a row opens a side panel) and wanted C's cards too, so the catalogue has a Cards / List switch. **Found while building:** (1) `useProviderKeys.load` wrote `{ ...keys.value, [p]: await fetch(p) }`, which copies the record before the await, so loading every provider at once kept only the last answer; Settings only ever loaded one provider, which hid it (regression test `useProviderKeys.test.ts`, red on the old code). (2) `BaseButton`'s `label` names icon-only buttons only; twelve cards with a visible "Edit" each need the model's name as `sr-only` text ("Edit qwen"), and the leading space must be inside the interpolation (`{{ " " + name }}`) or the template drops it. (3) Pitfall 79 (a scoped `display` beats `sm:hidden`). On a phone the Models editor drawn inside its page sat under the app header and the tab bar (title, Close and Save hidden); `<Teleport to="body">` fixed it, as `MemoryReviewDialog` does, with `global.stubs: { teleport: true }` in component tests. Cause not found: the Telegram setup help, also an in-page `ContextDrawer` in Settings, draws above the header on a phone, so this is not true of every in-page drawer. (4) The phone sheet measured 379 px on a 390 px screen while `documentElement.clientWidth` said 390 and no ancestor had a transform: the cause is not confirmed (the reserved scrollbar gutter of pitfall 76 is the likely one); the sheet is as wide as the app header, so "full width" is tested against the header. **Open, not part of the redesign:** a local model's output cap follows the training context, not the serving one (Qwen3.6 serves 16,384 tokens with `--ctx-size 16384` but gets max tokens 87,381 = 262,144 / 3); check `orchestrator.ApplyMetadataDefaults` and the `/slots` read before relying on the numbers the editor now states.
- 2026-11-26 (v0.143.0): **Models, Reminders, Activity, Settings and Stacks sat in a 1120 px column with wide empty gutters.** Cause: the shell (`App.vue` `contentClass`) capped every route that lacked `meta.fullWidth`, so each new page had to remember the flag (Newsroom met the same trap on 2026-11-25, `learnings/autonomy.md`). Fix: the flag is gone and every shell page uses the full width; a view that wants a narrower form column caps it itself (`NewsroomView`, `DashboardView` keep 1072 px). Checked at 1760 px on every tab of those pages; only the four Models desktop snapshots changed. The `/design` snapshots still fail on main too, despite the v0.142.0 refresh above (not this change); `telegram-help` failed once under the full suite and passes alone.
- 2026-11-26 (v0.145.0, plan `assistant-calm-mobile`): **The assistant on a phone was 237 of 844 px of chrome, a failed turn read "Worked 1s", and a chat opened 334 px above its latest message.** Measured in the browser with Playwright at CSS pixels (a first read off device-scale-2 screenshots doubled the chrome; measure with `getBoundingClientRect`, never off the image). The open-at-bottom miss was `content-visibility: auto` on finished turns (pitfall 80). Built: one bar on the phone Assistant page, a one-row composer with a + menu, the tab bar hidden while typing (`useComposerFocus`), a failure card from `describeRunFailure`, activity lines that name the work (`summarizeSteps`), the chat at full width (owner: "no left and right gaps"), and every automation's page in the audit's tabs. Traps: a fixture with the *log's* raw error made the failure look worse than vertex stores it (sessions keep a sentence; read the stored session, not the log); `DataTable`'s phone card is shared by seven lists, so the automation rows use a new optional `mobile-row` slot instead of changing it; adding a provider shifts the Models snapshots because the Providers tab stays mounted. Evidence: [2026-11-26 review](../audits/2026-11-26-assistant-automations-service-review.md), `e2e/assistant.visual.spec.ts`, `e2e/automations.visual.spec.ts`.
