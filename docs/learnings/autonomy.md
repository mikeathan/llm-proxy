## Root causes and fixes that held

- 2026-11-19 (Reminders stack, ADR-0068): **a stack's database file must not be created at start.** The first build opened `reminders.db` in `Start`; the app boot tests then failed with "directory not empty" because the host stops a stack from `context.AfterFunc` (asynchronous) while the test removed its temp folder. The store creates its file on the first write and reads a missing file as empty (`stacks/reminders/store.go`, `TestStore_NoFileUntilTheFirstWriteAndReadsOfNothingAreEmpty`).
- 2026-11-19: **an off module must arm no timer** (an overdue reminder's zero-length timer spun the loop), and **the one-time copy must run inside `Start`** (a reminder set at boot took id 1 and made the copy fail forever); both found by review, not by the first tests (the fake clock hides the spin). A factory reset keeps `orchestrator.db`, so reminders keep surviving it.
- 2026-11-19: **the cron grammar cannot go in the SDK** (the SDK requires nothing; core may not import an SDK sub-package): a `schedule` port keeps the one parser in the core. The stack's own tests use a small test evaluator; `internal/app/stackhost_reminders_test.go` runs the stack over the real grammar.
- 2026-11-19: **`reminders.disabled` sits in a block the Settings form saves whole**, so `applySettingsFields` keeps the stored value.
- 2026-11-20 (Newsroom stack): **`Runner.Run` must be serialised.** The timer's pass and a manual run from the screen both read, record and deliver one topic; without a lock both see the same items as unseen (a double notice once a send exists). `Runner.running` is the lock; `TestTwoRunsAtOnceSendOneNotice` fails with `-race` when it is removed. **`check-complexity` also scans `stacks/*`**, so a stack function over 12 fails the gate (`parseAnalysis`, `Feed` were split). The model port (`stackport.Model`) never returns the provider's words to the stack (a provider error can echo the prompt) and logs only sizes, duration, local or cloud and the result.
- **Tried:** reading the free sources from the dev Mac (2026-11-20) for Topic Watch → public Telegram preview, Hacker News (Algolia), Mastodon tag timelines and GitHub `releases.atom` answered 200 keyless; Reddit `.rss` and Bluesky `searchPosts` answered 403. **Lesson:** a Telegram preview page is plain markup with `data-post="chan/id"`, a `tgme_widget_message_text` div and a `<time datetime>`; a channel with no public preview has no message markup, so the reader must answer "source failing", not "nothing new". Recorded responses are in `stacks/newsroom/sources/testdata/`; they came from the dev Mac, not vertex, so re-check from vertex. Evidence: [topic-watch.md](../PLANS/autonomy/topic-watch.md).
- 2026-11-20 (Newsroom screens): **the server keeps one status per topic, not per source**, so the Sources tab shows a source's state as the last check of the topics that read it and "Check now" runs the topic; a per-source test needs a new route. **Home ships minimal**, so the Newsroom card is on a shipped Newsroom board, not on Home. **A `src/utils` file cannot export an interface** (the lint rule): new shapes go in `src/types/`.

- 2026-11-20 Newsroom, first run on vertex: (1) Edit, Delete and Run answered "no route": the core hands a stack the **real path** (`/topics/1`) with the id also in `Params`, not the `{id}` pattern, and the stack's tests had passed the pattern. Tests must pass real paths (`topicPath`, now `watchPath` in `stacks/newsroom/stack_test.go`); Reminders already matched by prefix. Mutation check: matching on the raw path fails 3 tests. (2) An empty feed was JSON `null` (a nil Go slice), and the page's `feed.length` crashed the whole Newsroom, which a topic that had only recorded its baseline triggered. Return `[]` from Go and read `?? []` in the service.
- **Tried:** adding a Telegram source on vertex (2026-11-20) by pasting `https://t.me/s/aipost` as the channel → "a channel name is 4 to 32 letters…" on every check. **Lesson:** the owner pastes what the browser shows, not the bare name; reduce pasted forms when the topic is saved and again when a stored spec is built (`sources.ChannelName`), but keep `TelegramChannel.Fetch` strict (a test requires a refusal before any request, which protects the `t.me` path). Help is one card per source kind (`SOURCE_GUIDES`), also shown under each source in the form.
- 2026-11-20 Newsroom redesign (owner feedback on vertex): **a "topic" that is only a name plus sources cannot say what to look for**, so it reported every post of the channel and the owner could not find where to set anything up; the Topics and Sources tabs were two views of one object. **Lesson:** put the filter (`look_for`, keywords) on the one object and give the page one place to set it up (ADR-0073). Also: a baseline that shows nothing makes a new watch look broken; it now shows up to five findings marked "First check". **Tried and kept:** fail open on a bad model answer (a weak local model must mean no filtering, never hidden items). Trap: tests that expected an empty feed after a baseline needed `forgetFirstFindings`.
- 2026-11-21 Newsroom, "Check now" on a Telegram-only watch showed a failure on vertex: the reader's 10-minute politeness floor (`ErrTooSoon`) was skipped in `Runner.read`, so a watch whose only source was waiting had `answered == 0` and was stored as `failing` ("no source could be read"). Now every-source-waiting answers `waiting` and records nothing (`watches/runner.go`, test `TestWaitingOutTheFloorIsNeitherFailingNorRecorded`); the page shows an info toast and a real `failing` outcome is an error toast (it used to say "Checked: nothing new"). Found by reading `/admin/api/newsroom/watches` on vertex: `last_detail: "no source could be read"`.
- 2026-11-21 Newsroom, "9 findings, every Why says *not* a model release" on vertex: the model answered the relevance question with a `matches` list that held **every** item, each with a reason such as "Benchmark, not new model release", and the code kept any listed item, so the filter hid nothing. **Lesson:** a list of keepers cannot say no; ask for a verdict (`relevant` true/false) on every item, put `why` first so a small model reasons before it decides, and never read the reason text to decide. Fail open stays (no verdict keeps the item). Regression: `TestAnItemTheModelCalledIrrelevantIsDroppedWhateverItsReasonSays`. Also: a Telegram post has no title, so its title is the start of its text; the entry showed both (`utils/newsroom/entryText.ts`). Not built: a per-day summary line (see the Morning Paper plan) until the filtered feed is seen for a day.
- 2026-11-21 Newsroom feed (owner feedback on vertex, after the verdict fix): the owner still saw an off-topic post (Neuralink) in the feed. **Lesson:** "no verdict keeps the item" was fail-open for the one thing the owner asked to filter; with `look_for` set the filter is now strict (only `relevant: true`; no verdict, no model, no usable answer shows nothing and retries, and the row names what was left out). The keyword gate (must-contain / skip) still runs first and is unchanged. Entries 1–9 on vertex predated the fix; the seen ledger, not the journal, feeds `Recent`, so clearing the feed does not weaken repeat detection (a repeat of a cleared title is only not folded). **Duplicate text, second try:** a Telegram title is whitespace-collapsed and its text keeps `\n\n`, so compare after collapsing both (`utils/newsroom/entryText.ts`); the test now uses the real string. **Tool trap:** the "New" pill ignored `read`, so Mark read left it; the unread dot already says it, so the pill is gone. Screenshot recipe: Vite on :5197, base path `/admin/`, `/admin/api/auth/status` must answer `{set_up,setup_open,authenticated,elevated,encrypted}`, headless Chromium from `~/Library/Caches/ms-playwright` when the pinned build is missing.
- 2026-11-21 Newsroom source look-up (owner asked to search public channels and topics from the watch form): **Telegram has no keyless search**; `t.me/s/<name>` answers only for a known name, and a name that is not a channel answers a 302 to `t.me/<name>` (a refused redirect or a page with no messages, both read as "no public preview"). **Mastodon is the exception**: `/api/v2/search?type=hashtags` and `/api/v1/trends/tags` answer keyless on mastodon.social (a small server may share no trends: an empty list is "no trending tags", not an error). Checked from the dev Mac on 2026-11-21, not from vertex. Built as `sources/lookup.go` + two stack reads (ADR-0074). **Traps:** the look-up must use its own `TelegramChannel` reader, not the runner's, or it takes the 10-minute read slot and the next Check now says "waiting"; a cache key must be the cleaned-up value (`@AIpost`, `t.me/s/aipost` and `aipost` are one channel); do not remember "internet off" or a timeout. `go test ./...` fails inside `stacks/newsroom` (module roots, go.work): name the packages (`go test . ./sources ./watches`).
- 2026-11-21 Newsroom feed rows (owner: a Telegram post's title was the first 200 characters of the post, and expanding it showed a clipped copy): the model call that already judges relevance now also writes a `headline` and `summary` per item (`digests` in `watches/analyst.go`, kept on `Entry`); the original title, link and text stay and show when the row is opened. Digests are optional, so a weak model that skips them costs only the nicer title. Not checked: how the real local model on vertex answers the extra field. "Check now" disables every button while it runs, so the row now says "Checking…" (`runningId` in `useNewsroom`). **Trap:** a backtick inside a double-quoted shell string is command substitution, so write docs with the file tools, not `printf`.
- 2026-11-21 Newsroom Briefs (design and first build): **a stack's model call is one in flight, 200 a day, 2000 answer tokens and refuses a second caller** (`stackport/model.go`), so a brief and the hourly watches must take turns (`modelgate.go`) and a collector must not call the model. **Google News RSS search is keyless and reaches Reuters and AP** (`site:reuters.com`), but its description repeats the title (no snippet), its link is a Google page (a fresh browser landed on a "Before you continue" consent page, not the article), and a title ends " - Publisher"; so `NewsSearch` clears Text and moves the publisher out. **curl with a browser header is not evidence for the app's fetch**: TechCrunch and Euronews answered 403/406 to curl and worked through vertex's look-up, while AP and DW did the opposite; test every source through `/admin/api/newsroom/sources/lookup`. **A reader's politeness floor is held per reader instance, keyed by kind, label, instance and target**, so the same Telegram channel under another label gets its own slot; briefs therefore read only kinds with no floor until a slot keyed by channel exists. The test for a clock-driven loop that must run "whatever time it is" sets ready-by to now plus 30 minutes.
- 2026-11-21 Newsroom (owner ran a check after switching to a cloud model and got "nothing new"): the verdict was right (3 unseen posts, 1 repeat, 2 off-topic; nothing on the channels was a model release), but **one of six Telegram sources, `AnthropicAI_moon`, has no public preview** (`t.me/s/<name>` answers 200 with no message markup) and was never read. The run showed it only as faint detail text, worded "telegram X: telegram X: the source answered in a shape this reader does not understand", and a partial failure left no flag once a later run ended in another status. **Lesson:** a run's status says what it found, not whether every source was read: keep unread sources as their own field on the watch (`last_problems`), and let each reader name itself once.
- 2026-11-21 Newsroom (owner: an old DeepSeek post from 17 October showed as "2 minutes ago" under Today, and a new check still showed raw post text): **the entry time was the time the watch found the post**, and `Item.At` (every source sets it) was read nowhere, so the first check of a Telegram channel presented its whole back-catalogue as news. Fixed with a per-watch `max_age` (default 72 h) applied in `Runner.Run` before the model call (stale items recorded as seen, undated items kept) and `Entry.Posted` shown on the row. The ledger keeps items 60 days, longer than the 30-day maximum window, so a dropped post cannot come back as new. Missing headlines on vertex (v0.119.0), cause found by replaying the prompt on the owner's primary (Qwen3.6 35B A3B, thinking off as production sends it): the model wrote the headlines and summaries but **left the `"item": N` field off every entry**, and `checkedDigests` drops a digest that names no shown item, so all of them were discarded. Fixed twice over: the prompt now says every entry must carry its `item`, and an answer where no entry of a list is numbered is read by position (`numberedByPosition`, `numberedDigests` in `watches/analyst.go`; a mixed or short answer is never guessed at). **Trap for replays:** with thinking left on, Qwen3.6 spends the whole 2000-token cap reasoning and returns an empty answer (vertex caps a reply at 5461 tokens, context 16384); replay with `chat_template_kwargs.enable_thinking=false` and `thinking_budget_tokens=0` like `stackModelAsk`. The row also falls back to a plain first-sentence headline (`frontend/src/utils/newsroom/entryHeadline.ts`).
- 2026-11-22 Newsroom Briefs edition pass: **the stack's 200 model calls a day is now `newsroom.model_calls_per_day`** (default 200, ceiling 2000, read at every call, `stackport.Model.Limit` is a func), and the model port stays on while either module is on (it used to follow only Watches, so a Briefs-only install would have had no model). The edition is composed by `brief/compose.go` (pure: pool, topics, shown record, model in; issue out) and written by `brief/publish.go`. **Test trap:** a "shown story is dropped" test passes for the wrong reason when the shown story would have fallen outside the 15-candidate cap anyway; give it the most outlets, and mutate the rule to see the test fail. **Traps:** `go test ./...` does work in `stacks/newsroom` with `GOWORK=off` (the module is not in go.work); an edition with no ready time is a manual one and must never count as the scheduled one. Replayed against vertex's Qwen3.6 35B A3B (thinking off) on 2026-11-22 with a six-story sample including an injected headline: valid JSON, every `item` present, empty summaries for headline-only stories, injection ignored (one sample; the top-stories call was not replayed). Replay recipe: dump `sectionSystem`/`sectionPrompt` from a temporary test, POST to `/v1/chat/completions` with `chat_template_kwargs.enable_thinking=false` and `thinking_budget_tokens=0`.
- 2026-11-22 Newsroom Briefs tab: a stack page's tabs are a router param pattern (`NEWSROOM_TABS` in `types/routes.ts`) **and** a test's own copy of the route (`Newsroom.component.test.ts` builds its router by hand), so adding a tab fails that test until its pattern is updated. A form that edits only part of a stored object (the topic form edits searches and feeds) must send the rest back unchanged, or saving silently drops what the assistant added (`topicEdit` in `utils/newsroom/briefForm.ts`). `vue-tsc` and `eslint` called alone printed nothing in this repo and proved nothing; only `npm run build` ran them (it caught a type error in a test). **Screenshot trap:** `text-state-warning` is not a token (the warning state shares `state-running`, see `constants/status.ts`), so text using it renders in the default colour with no error; the radio and look-up components still use it. Vite binds `localhost` on IPv6 here, so a screenshot script must use `http://localhost:5197`, not 127.0.0.1; the segmented control's options are not `role=button`, click them by text.
- 2026-11-22 Newsroom Briefs sources: **"Write it now" on a never-collected topic wrote an edition of empty sections** because topics are collected only inside an edition's collection window (`Collector.Tick`); the manual write now calls `CollectStale` first. The sections said "Nothing new here since the last edition" for a topic that was never read: it now says it was never read. **Feed addresses written from memory are partly wrong** (Yahoo Finance and New Scientist failed live checks; Reuters and the AP have no public feed): every catalog feed was fetched and parsed before it went in, and publishers with no feed are `site:` searches. A chip box that commits on blur turns a half-typed word into a chip, so a box with `accept` keeps a refused word in the field. A list the owner keeps does not belong in the module's settings document, whose save replaces all of it (`Config.Save`).
- 2026-11-22 Newsroom Briefs pasted feeds: the topic form reuses the watch form's look-up for a pasted feed link (one request per distinct link, aborted when the row goes or the link is removed) and keeps a found feed in "My sources" under the title the feed gives itself, cut to the name limit; a feed's title is text from the internet and is shown as text only. - 2026-11-25 Newsroom reader spacing (after v0.132.0 went live, ADR-0086 amended). **What made the page look empty:** the Newsroom route was not `fullWidth` (Network, Agents and Radio are), so the 1120 px page cap left wide gutters; the 11 rem index column held three links over an empty page height; `md:grid-cols-3` for the other top stories left two thirds empty with one story and squeezed three into ~200 px cells (story actions stacked one per line); and the story meta row was a flex row, so "· posted …" wrapped onto its own line. **Fix:** Brief tab full width (the other tabs keep 1072 px inside `NewsroomView`, the forms looked stretched), the index is the sticky row at every width, top-story columns follow the count, meta is flowing text with the time kept beside the last outlet, the heavy double rules became hairlines. **Trap:** the visual fixture had one other top story and no topics, so it showed none of this; reproduce with the live shape (three other top stories, eight outlets, topics so the actions render) at the owner's width (~1760 px).
