## Root causes and fixes that held

- 2026-11-19 (Reminders stack, ADR-0068): **a stack's database file must not be created at start.** The first build opened `reminders.db` in `Start`; the app boot tests then failed with "directory not empty" because the host stops a stack from `context.AfterFunc` (asynchronous) while the test removed its temp folder. The store creates its file on the first write and reads a missing file as empty (`stacks/reminders/store.go`, `TestStore_NoFileUntilTheFirstWriteAndReadsOfNothingAreEmpty`).
- 2026-11-19: **an off module must arm no timer** (an overdue reminder's zero-length timer spun the loop), and **the one-time copy must run inside `Start`** (a reminder set at boot took id 1 and made the copy fail forever); both found by review, not by the first tests (the fake clock hides the spin). A factory reset keeps `orchestrator.db`, so reminders keep surviving it.
- 2026-11-19: **the cron grammar cannot go in the SDK** (the SDK requires nothing; core may not import an SDK sub-package): a `schedule` port keeps the one parser in the core. The stack's own tests use a small test evaluator; `internal/app/stackhost_reminders_test.go` runs the stack over the real grammar.
- 2026-11-19: **`reminders.disabled` sits in a block the Settings form saves whole**, so `applySettingsFields` keeps the stored value.
- 2026-11-20 (Newsroom stack): **`Runner.Run` must be serialised.** The timer's pass and a manual run from the screen both read, record and deliver one topic; without a lock both see the same items as unseen (a double notice once a send exists). `Runner.running` is the lock; `TestTwoRunsAtOnceSendOneNotice` fails with `-race` when it is removed. **`check-complexity` also scans `stacks/*`**, so a stack function over 12 fails the gate (`parseAnalysis`, `Feed` were split). The model port (`stackport.Model`) never returns the provider's words to the stack (a provider error can echo the prompt) and logs only sizes, duration, local or cloud and the result.
- **Tried:** reading the free sources from the dev Mac (2026-11-20) for Topic Watch → public Telegram preview, Hacker News (Algolia), Mastodon tag timelines and GitHub `releases.atom` answered 200 keyless; Reddit `.rss` and Bluesky `searchPosts` answered 403. **Lesson:** a Telegram preview page is plain markup with `data-post="chan/id"`, a `tgme_widget_message_text` div and a `<time datetime>`; a channel with no public preview has no message markup, so the reader must answer "source failing", not "nothing new". Recorded responses are in `stacks/newsroom/sources/testdata/`; they came from the dev Mac, not vertex, so re-check from vertex. Evidence: [topic-watch.md](../PLANS/autonomy/topic-watch.md).
- 2026-11-20 (Newsroom screens): **the server keeps one status per topic, not per source**, so the Sources tab shows a source's state as the last check of the topics that read it and "Check now" runs the topic; a per-source test needs a new route. **Home ships minimal**, so the Newsroom card is on a shipped Newsroom board, not on Home. **A `src/utils` file cannot export an interface** (the lint rule): new shapes go in `src/types/`.

- 2026-11-20 Newsroom, first run on vertex: (1) Edit, Delete and Run answered "no route": the core hands a stack the **real path** (`/topics/1`) with the id also in `Params`, not the `{id}` pattern, and the stack's tests had passed the pattern. Tests must pass real paths (`topicPath`, now `watchPath` in `stacks/newsroom/stack_test.go`); Reminders already matched by prefix. Mutation check: matching on the raw path fails 3 tests. (2) An empty feed was JSON `null` (a nil Go slice), and the page's `feed.length` crashed the whole Newsroom, which a topic that had only recorded its baseline triggered. Return `[]` from Go and read `?? []` in the service.
- **Tried:** adding a Telegram source on vertex (2026-11-20) by pasting `https://t.me/s/aipost` as the channel → "a channel name is 4 to 32 letters…" on every check. **Lesson:** the owner pastes what the browser shows, not the bare name; reduce pasted forms when the topic is saved and again when a stored spec is built (`sources.ChannelName`), but keep `TelegramChannel.Fetch` strict (a test requires a refusal before any request, which protects the `t.me` path). Help is one card per source kind (`SOURCE_GUIDES`), also shown under each source in the form.
- 2026-11-20 Newsroom redesign (owner feedback on vertex): **a "topic" that is only a name plus sources cannot say what to look for**, so it reported every post of the channel and the owner could not find where to set anything up; the Topics and Sources tabs were two views of one object. **Lesson:** put the filter (`look_for`, keywords) on the one object and give the page one place to set it up (ADR-0073). Also: a baseline that shows nothing makes a new watch look broken; it now shows up to five findings marked "First check". **Tried and kept:** fail open on a bad model answer (a weak local model must mean no filtering, never hidden items). Trap: tests that expected an empty feed after a baseline needed `forgetFirstFindings`.
- 2026-11-21 Newsroom, "Check now" on a Telegram-only watch showed a failure on vertex: the reader's 10-minute politeness floor (`ErrTooSoon`) was skipped in `Runner.read`, so a watch whose only source was waiting had `answered == 0` and was stored as `failing` ("no source could be read"). Now every-source-waiting answers `waiting` and records nothing (`watches/runner.go`, test `TestWaitingOutTheFloorIsNeitherFailingNorRecorded`); the page shows an info toast and a real `failing` outcome is an error toast (it used to say "Checked: nothing new"). Found by reading `/admin/api/newsroom/watches` on vertex: `last_detail: "no source could be read"`.
- 2026-11-21 Newsroom, "9 findings, every Why says *not* a model release" on vertex: the model answered the relevance question with a `matches` list that held **every** item, each with a reason such as "Benchmark, not new model release", and the code kept any listed item, so the filter hid nothing. **Lesson:** a list of keepers cannot say no; ask for a verdict (`relevant` true/false) on every item, put `why` first so a small model reasons before it decides, and never read the reason text to decide. Fail open stays (no verdict keeps the item). Regression: `TestAnItemTheModelCalledIrrelevantIsDroppedWhateverItsReasonSays`. Also: a Telegram post has no title, so its title is the start of its text; the entry showed both (`utils/newsroom/entryText.ts`). Not built: a per-day summary line (see the Morning Paper plan) until the filtered feed is seen for a day.
- 2026-11-21 Newsroom feed (owner feedback on vertex, after the verdict fix): the owner still saw an off-topic post (Neuralink) in the feed. **Lesson:** "no verdict keeps the item" was fail-open for the one thing the owner asked to filter; with `look_for` set the filter is now strict (only `relevant: true`; no verdict, no model, no usable answer shows nothing and retries, and the row names what was left out). The keyword gate (must-contain / skip) still runs first and is unchanged. Entries 1–9 on vertex predated the fix; the seen ledger, not the journal, feeds `Recent`, so clearing the feed does not weaken repeat detection (a repeat of a cleared title is only not folded). **Duplicate text, second try:** a Telegram title is whitespace-collapsed and its text keeps `\n\n`, so compare after collapsing both (`utils/newsroom/entryText.ts`); the test now uses the real string. **Tool trap:** the "New" pill ignored `read`, so Mark read left it; the unread dot already says it, so the pill is gone. Screenshot recipe: Vite on :5197, base path `/admin/`, `/admin/api/auth/status` must answer `{set_up,setup_open,authenticated,elevated,encrypted}`, headless Chromium from `~/Library/Caches/ms-playwright` when the pinned build is missing.
- 2026-11-21 Newsroom source look-up (owner asked to search public channels and topics from the watch form): **Telegram has no keyless search**; `t.me/s/<name>` answers only for a known name, and a name that is not a channel answers a 302 to `t.me/<name>` (a refused redirect or a page with no messages, both read as "no public preview"). **Mastodon is the exception**: `/api/v2/search?type=hashtags` and `/api/v1/trends/tags` answer keyless on mastodon.social (a small server may share no trends: an empty list is "no trending tags", not an error). Checked from the dev Mac on 2026-11-21, not from vertex. Built as `sources/lookup.go` + two stack reads (ADR-0074). **Traps:** the look-up must use its own `TelegramChannel` reader, not the runner's, or it takes the 10-minute read slot and the next Check now says "waiting"; a cache key must be the cleaned-up value (`@AIpost`, `t.me/s/aipost` and `aipost` are one channel); do not remember "internet off" or a timeout. `go test ./...` fails inside `stacks/newsroom` (module roots, go.work): name the packages (`go test . ./sources ./watches`).
