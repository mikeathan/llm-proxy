A research run took 736 seconds. The search provider (Tavily) kept answering HTTP 432, "usage limit used up", and the code treated that like a temporary error, so the model and its helpers kept trying.

Make HTTP 402, 432 and 433 from a search provider terminal: the search tool becomes unavailable, the same way a rejected API key already does, so the agent loop stops retrying. The reason text must read exactly `<provider> usage limit reached (HTTP <code>)`, for example `tavily usage limit reached (HTTP 432)`.

HTTP 429 (a rate limit that clears by waiting) must keep behaving as before.
